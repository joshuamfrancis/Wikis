# WireGuard over WebSockets — Hub-and-Spoke Setup Guide

## Architecture Overview

```
[Windows Server 2025]          [RHEL 10 AWS EC2]
  On-Prem Data Center           (future: on-prem)
  wg-client1                    wg-client2
  10.0.0.2/32                   10.0.0.3/32
        |                              |
        |  WebSocket tunnel            |  WebSocket tunnel
        +-----------> [AWS EC2] <------+
                    RHEL 10 Server
                    wg-server
                    10.0.0.1/24
                    Public IP: x.x.x.x
```

The server acts as a **hub** — clients route traffic destined for each other through it. This is a standard WireGuard hub-and-spoke topology.

---

## Why WireGuard over WebSockets?

Raw WireGuard uses UDP port 51820. On-prem data centers often:
- Block non-standard UDP ports outbound
- Only allow TCP 443/80 egress

The solution is to **wrap WireGuard UDP in a WebSocket (TCP) tunnel** using [`wstunnel`](https://github.com/erebe/wstunnel).

---

## Component Stack

| Layer | Tool |
|---|---|
| VPN | WireGuard |
| WebSocket wrapper | `wstunnel` |
| Server OS | RHEL 10 (EC2) |
| Client 1 OS | Windows Server 2025 |
| Client 2 OS | RHEL 10 (EC2 → future on-prem) |

## Server Setup (RHEL 10, AWS EC2)

### 1. Security Group / Firewall

Open inbound on EC2 Security Group:
- **TCP 443** (wstunnel WebSocket listener)
- Optionally TCP 80 (redirect to 443)

If `firewalld` is active on the instance:
```bash
firewall-cmd --permanent --add-port=443/tcp
firewall-cmd --permanent --add-port=51820/udp
firewall-cmd --reload
```

### 2. Install WireGuard

```bash
sudo dnf install wireguard-tools -y
```

### 3. Generate Server Keys

```bash
wg genkey | tee /etc/wireguard/server_private.key | wg pubkey > /etc/wireguard/server_public.key
chmod 600 /etc/wireguard/server_private.key
```

### 4. WireGuard Config

Create `/etc/wireguard/wg0.conf`:

```ini
[Interface]
Address = 10.0.0.1/24
ListenPort = 51820
PrivateKey = <server_private_key>
PostUp   = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE

# Client 1 - Windows Server 2025
[Peer]
PublicKey = <client1_public_key>
AllowedIPs = 10.0.0.2/32

# Client 2 - RHEL 10
[Peer]
PublicKey = <client2_public_key>
AllowedIPs = 10.0.0.3/32
```

Enable IP forwarding so clients can reach each other:

```bash
echo "net.ipv4.ip_forward=1" >> /etc/sysctl.d/99-wireguard.conf
sysctl -p /etc/sysctl.d/99-wireguard.conf
```

### 5. Install wstunnel

Download the latest release from [github.com/erebe/wstunnel/releases](https://github.com/erebe/wstunnel/releases):

```bash
curl -Lo wstunnel https://github.com/erebe/wstunnel/releases/latest/download/wstunnel_linux_amd64
chmod +x wstunnel
mv wstunnel /usr/local/bin/
```

### 6. Create wstunnel systemd Service

Create `/etc/systemd/system/wstunnel.service`:

```ini
[Unit]
Description=wstunnel WebSocket server
After=network.target

[Service]
ExecStart=/usr/local/bin/wstunnel server --restrict-to 127.0.0.1:51820 wss://0.0.0.0:443
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Enable and start both services:

```bash
systemctl daemon-reload
systemctl enable --now wstunnel
systemctl enable --now wg-quick@wg0
```

## Client 2 Setup (RHEL 10, AWS EC2)

### 1. Install WireGuard

```bash
sudo dnf install wireguard-tools -y
```

### 2. Generate Keys

```bash
wg genkey | tee /etc/wireguard/client_private.key | wg pubkey > /etc/wireguard/client_public.key
chmod 600 /etc/wireguard/client_private.key
```

### 3. Install and Run wstunnel

```bash
curl -Lo wstunnel https://github.com/erebe/wstunnel/releases/latest/download/wstunnel_linux_amd64
chmod +x wstunnel
mv wstunnel /usr/local/bin/
```

Create `/etc/systemd/system/wstunnel.service`:

```ini
[Unit]
Description=wstunnel WebSocket client
After=network.target

[Service]
ExecStart=/usr/local/bin/wstunnel client -L "udp://51820:127.0.0.1:51820?timeout_sec=0" wss://<SERVER_PUBLIC_IP>:443
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now wstunnel
```

### 4. WireGuard Config

Create `/etc/wireguard/wg0.conf`:

```ini
[Interface]
Address = 10.0.0.3/24
PrivateKey = <client2_private_key>
DNS = 1.1.1.1

[Peer]
PublicKey = <server_public_key>
# Points to local wstunnel listener — not the server directly
Endpoint = 127.0.0.1:51820
AllowedIPs = 10.0.0.0/24
PersistentKeepalive = 25
```

```bash
systemctl enable --now wg-quick@wg0
```

> **Migration note:** When Client 2 moves from AWS to on-prem, only the wstunnel `ExecStart` line changes (update `<SERVER_PUBLIC_IP>`). The WireGuard config is identical because `Endpoint = 127.0.0.1:51820` is environment-agnostic.

## Client 1 Setup (Windows Server 2025)

### 1. Install WireGuard

Download and install the official MSI from [wireguard.com/install](https://www.wireguard.com/install/).

### 2. Generate Keys

Open the WireGuard GUI, click **Add Tunnel → Add empty tunnel**. Keys are generated automatically and displayed in the editor. Note the public key to register on the server.

Alternatively, use PowerShell if `wg.exe` is on your PATH:
```powershell
wg genkey | Out-File -Encoding ascii client_private.key
Get-Content client_private.key | wg pubkey | Out-File -Encoding ascii client_public.key
```

### 3. Install wstunnel

Download the Windows binary from [github.com/erebe/wstunnel/releases](https://github.com/erebe/wstunnel/releases) (`wstunnel_windows_amd64.exe`). Place it at `C:\wstunnel\wstunnel.exe`.

### 4. Run wstunnel as a Windows Service

Install [NSSM](https://nssm.cc/) to manage wstunnel as a proper service:

```powershell
nssm install wstunnel "C:\wstunnel\wstunnel.exe"
nssm set wstunnel AppParameters 'client -L "udp://51820:127.0.0.1:51820?timeout_sec=0" wss://<SERVER_PUBLIC_IP>:443'
nssm set wstunnel Start SERVICE_AUTO_START
nssm start wstunnel
```

> **Important:** wstunnel **must be running** before WireGuard starts, as WireGuard needs the local UDP listener on 127.0.0.1:51820 to be present at startup.

### 5. WireGuard Config

In the WireGuard GUI, paste the following config (or save as a `.conf` file and import):

```ini
[Interface]
Address = 10.0.0.2/24
PrivateKey = <client1_private_key>
DNS = 1.1.1.1

[Peer]
PublicKey = <server_public_key>
# Points to local wstunnel listener — not the server directly
Endpoint = 127.0.0.1:51820
AllowedIPs = 10.0.0.0/24
PersistentKeepalive = 25
```

Activate the tunnel in the WireGuard GUI or via:

```powershell
wg-quick up wg0
```

## Inter-Client Traffic Flow

When Client 1 (10.0.0.2) communicates with Client 2 (10.0.0.3):

```
Client 1
  └─► wstunnel (local UDP 51820)
        └─► WSS TCP 443
              └─► Server wstunnel
                    └─► WireGuard wg0 (routes 10.0.0.0/24)
                          └─► wstunnel on Client 2
                                └─► Client 2 WireGuard interface
```

This works because both clients have `AllowedIPs = 10.0.0.0/24`, routing all VPN subnet traffic through the server hub. The server's `iptables FORWARD` rule permits forwarding between peers.

## Key Operational Notes

### TLS Certificates
For production, use a real TLS certificate instead of a self-signed cert. This makes WebSocket traffic indistinguishable from normal HTTPS traffic, which is important for traversing restrictive firewalls.

```bash
# Install certbot on the server
sudo dnf install certbot -y
sudo certbot certonly --standalone -d <your-domain>

# Update wstunnel ExecStart to reference the cert:
# wstunnel server --tls-certificate /etc/letsencrypt/live/<domain>/fullchain.pem \
#                 --tls-private-key /etc/letsencrypt/live/<domain>/privkey.pem \
#                 --restrict-to 127.0.0.1:51820 wss://0.0.0.0:443
```

### PersistentKeepalive
`PersistentKeepalive = 25` is essential for clients behind NAT/firewalls. It sends a keepalive packet every 25 seconds to maintain the connection state and ensure the server can push return traffic back to the client.

### Key Exchange
Never transmit private keys over the network. The workflow for registering a new client is:
1. Generate keypair **on the client**
2. Share only the **public key** with the server administrator
3. Server administrator adds the public key to `wg0.conf` under a new `[Peer]` block
4. Run `wg addconf wg0 <(wg showconf wg0)` or restart `wg-quick@wg0` to apply

### Verifying the Tunnel

On the server, check peer handshake status:
```bash
sudo wg show
```

Test connectivity between clients:
```bash
# From Client 2, ping Client 1
ping 10.0.0.2

# From Client 1 (PowerShell), ping Client 2
ping 10.0.0.3
```
