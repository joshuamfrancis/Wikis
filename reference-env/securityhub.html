IAM / Resource Policies

  • Each NLZ source account needs an EventBridge rule targeting the hub account bus ARN
  • The hub account custom bus needs a resource policy allowing events:PutEvents from each NLZ account principal
  • Use aws:PrincipalOrgPaths condition to scope to OU — future accounts auto-inherit

EventBridge Rule (source accounts)

  • Event pattern: {"source":["aws.securityhub"]}
  • Target: custom bus ARN in NLZ Hub Account
  • Dead-letter queue on rule for failed deliveries
  • Deploy via CloudFormation StackSets scoped to NLZ OU

Lambda Enrichment (optional)

  • Add OU path, environment tag, account alias to each finding
  • Normalize ASFF severity to internal tiers
  • Suppress known-false-positive finding types
  • Forward critical findings to SNS → PagerDuty

S3 Partitioning

  • findings/year=/month=/account=/
  • Glue Crawler auto-discovers partitions
  • Athena queries stay cheap with partition pruning
  • Enable S3 Object Lock for compliance retention

Does NOT conflict with

  • Org-wide Security Hub delegated admin
  • Central security account still aggregates everything
  • No separate Security Hub admin designation needed
  • NLZ accounts remain standard Security Hub members

StackSets Deployment

  • Deploy EB rule + IAM role via StackSet targeting the NLZ OU
  • New accounts added to OU auto-get the rule
  • Hub account bus policy updated via automation (e.g. Control Tower lifecycle events)
  • CDK or Terraform for hub account pipeline resources
